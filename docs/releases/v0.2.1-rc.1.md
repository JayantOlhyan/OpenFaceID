# OpenFaceID v0.2.1-rc.1 Release Notes

## Release Information
* **Version**: `0.2.1-rc.1`
* **Release Phase**: Phase 9 (Open-Source Ecosystem & Contributor Readiness)
* **Date**: September 13, 2026
* **Commit**: Current `main`

---

## Executive Summary

Version `0.2.1-rc.1` establishes OpenFaceID as a production-credible, maintainable, and contributor-friendly open-source monorepo. This release focuses on developer experience, public API stability contracts, architectural boundary enforcement, comprehensive technical documentation, and responsible open-source governance.

---

## What's New in v0.2.1-rc.1

### 1. Developer CLI Enhancements
* **Machine-Readable `--json` Flag**: Pure, unpolluted JSON output across all major CLI subcommands (`status`, `doctor`, `security check`, `privacy check`, `camera`, `identity`, `presence`, `vision benchmark`, `config`). Automatically squelches logger output to stdout/stderr.
* **Standardized Numeric Exit Codes**: Documented exit codes (0 = Success, 1 = General Failure, 2 = Invalid Arguments, 3 = Camera Unavailable, 4 = Auth Unavailable, 5 = Security Failure, 6 = Privacy Restriction, 7 = Daemon Unavailable).
* **Developer Health Check**: `openfaceid doctor --dev` checks Node.js runtime, dev dependencies, build tools, and local permissions.

### 2. Public API Stability & Verification
* **API Stability Policy**: Formally established 5 stability tiers (`Stable`, `Experimental`, `Internal`, `Deprecated`, `Removed`) in `docs/api-stability.md`.
* **Automated Contract Invariants**: Added `tests/unit/api_contracts.test.ts` verifying state enums, config validation, cryptographic guarantees, and error code structures.
* **Architectural Boundaries**: Added `tests/unit/architecture_boundaries.test.ts` to statically enforce package layer direction and the 0 runtime npm dependency invariant.

### 3. Developer Code Samples (`examples/`)
* 8 runnable, automated examples covering:
  * Canonical state machine subscription and transitions (`examples/core-state.ts`)
  * Hardware camera discovery and capture (`examples/camera-access.ts`)
  * ArcFace 512D embedding and cosine matching (`examples/recognition.ts`)
  * Presentation Attack Detection / liveness evaluation (`examples/liveness.ts`)
  * PresenceTracker absence and multi-face drop (`examples/presence.ts`)
  * Daemon REST/SSE IPC client (`examples/ipc-client.ts`)
  * Programmatic CLI invocation and JSON parsing (`examples/cli-integration.ts`)
  * Workstation locking and loopback webhooks (`examples/automation.ts`)
  * Non-biometric synthetic fixtures (`examples/demo/fixtures.ts`)

### 4. Open-Source Governance & Community Tools
* Standardized issue templates (`.github/ISSUE_TEMPLATE/`), pull request template, Code of Conduct, and Governance guide.
* Strict biometric test data policy prohibiting real facial captures from the repository.

## Known Limitations & Security Disclosures

> [!WARNING]
> **Hardware Status & Signature Disclosures**
> 1. **macOS Gatekeeper Warning**: macOS desktop packages (`.dmg`, `.app`) are currently **UNSIGNED / NOT NOTARIZED** due to deferred Apple Developer ID certificate integration (RB-01). Users must manually bypass Gatekeeper.
> 2. **Windows & Linux Hardware Unverified**: While the code is implemented and builds successfully in CI, physical optical webcam hardware validation has only been performed on macOS (MAC-01). Windows and Linux remain **HARDWARE UNVERIFIED** (RB-02).
> 3. **In-Tree Analytical Formulations**: Vision modules (BlazeFace and ArcFace) are analytical TypeScript implementations, not deep neural network weight files. Accuracy is subject to ambient illumination conditions.
> 4. **No OS Login Bypass**: OpenFaceID operates at the desktop session layer and does not replace OS login screens or passwords.
